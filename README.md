# Параллельная сортировка слиянием в Linux

Одна задача, сортировка слиянием, распараллелена четырьмя способами. Цель — сравнить механизмы межпроцессного взаимодействия и понять, где параллелизм окупается. Курс «Операционные системы» (НГТУ НЭТИ).

| Файл | Как делится работа | Как передаются данные |
|---|---|---|
| `01_processes_shared_memory.c` | дерево процессов (`fork`) | разделяемая память (`mmap`) + POSIX-семафоры |
| `02_pthreads_mutex.c` | потоки (`pthread`) | общая память процесса + `mutex` |
| `03_processes_pipes.c` | дерево процессов (`fork`) | неименованные каналы (`pipe`) |
| `04_processes_tcp_sockets.c` | дерево процессов (`fork`) | TCP-сокеты на localhost |

## Результат

На массиве из 100 млн элементов (версия с потоками) рост числа потоков с 1 до 10 дал почти линейное ускорение. Максимум — **в 6,8 раза** при 50 потоках. Дальше накладные расходы на создание потоков съедают выигрыш.

Во всех версиях есть трассировка: временная метка, PID, дескриптор, глубина рекурсии.

## Сборка

```bash
gcc -O2 -o sort1 01_processes_shared_memory.c
gcc -O2 -o sort2 02_pthreads_mutex.c -lpthread
gcc -O2 -o sort3 03_processes_pipes.c
gcc -O2 -o sort4 04_processes_tcp_sockets.c

./sort1 4      # глубина дерева процессов
./sort2 8      # число потоков
```
